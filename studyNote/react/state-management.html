状态管理方面

学完这个要动手做一个登陆相关的

一、为什么要全局状态管理？

React 的数据流是单向的：数据只能自上而下通过 props 传递。

问题 1：层层传递 props（props drilling）

  • 祖先组件的数据要传到最底层孙子组件，就要一层一层地传。
  • 即使中间组件不需要这个数据，也必须传下去。

问题 2：跨页面、跨模块通信困难

  • 比如用户登录状态要在多个页面使用，每次都传 props 太麻烦。

全局状态管理解决的问题

  • 数据可以在任何地方读写（类似于一个全局仓库 Store）。
  • 避免重复、冗余的 props 传递。
  • 提升代码的可维护性和可扩展性。

二、Context API（轻量方案）

使用场景

  • 全局主题（浅色/深色）。
  • 多语言切换。
  • 用户信息（只需简单共享）。

1. 创建 Context Provider

// src/context/ThemeContext.js
import React, { createContext, useState } from "react";

// 1. 创建 Context（相当于创建一个全局的“仓库”）
export const ThemeContext = createContext();

// 2. 提供 Context（必须包裹在根组件上）
export function ThemeProvider({ children }) {
  const [theme, setTheme] = useState("light"); // 全局主题，默认 light

  return (
    // 使用 Provider 将状态传递给子组件
    <ThemeContext.Provider value={{ theme, setTheme }}>
      {children}
    </ThemeContext.Provider>
  );
}

2. 在组件中使用 Context

// src/components/ThemeSwitcher.js
import React, { useContext } from "react";
import { ThemeContext } from "../context/ThemeContext";

function ThemeSwitcher() {
  // 通过 useContext 获取全局状态和方法
  const { theme, setTheme } = useContext(ThemeContext);

  return (
    <button onClick={() => setTheme(theme === "light" ? "dark" : "light")}>
      当前主题: {theme}
    </button>
  );
}

export default ThemeSwitcher;

3. 在应用入口包裹 Provider

// src/main.js
import React from "react";
import ReactDOM from "react-dom";
import App from "./App";
import { ThemeProvider } from "./context/ThemeContext";

ReactDOM.render(
  // 将全局 Provider 包裹在应用最外层
  <ThemeProvider>
    <App />
  </ThemeProvider>,
  document.getElementById("root")
);

优点：简单、方便，适合小项目。 缺点：数据一旦更新，所有使用 useContext 的组件都会重新渲染，性能不好。

三、关于Redux的一些原理

Redux 是React最常用的集中状态管理工具，类似于Vue中的Pinia（Vuex），可以独立于框架运行 作用：通过集中管理的方式管理应用的状态

为什么要使用Redux？

  1. 独立于组件，无视组件之间的层级关系，简化通信问题
  2. 单项数据流清晰，易于定位bug
  3. 调试工具配套良好，方便调试

具体的使用步骤可以看下面，现在聊聊Redux的一些原理”

Redux数据流架构

Redux的难点是理解它对于数据修改的规则, 下图动态展示了在整个数据的修改中，数据的流向

为了职责清晰，Redux代码被分为三个核心的概念

三个概念分别是:

  1. state: 一个对象 存放着我们管理的数据
  2. action: 一个对象 用来描述你想怎么改数据
  3. reducer: 一个函数 根据action的描述更新state

四、Redux Toolkit（推荐，类似 Vue 的 Pinia）

Redux 是 React 里最经典的状态管理库，而 Redux Toolkit（简称 RTK）是 Redux 的官方升级版，极大简化了 Redux 的使用。

适用场景

  • 中大型项目。
  • 状态复杂（用户信息、购物车、权限控制、接口数据缓存）。
  • 需要 可预测、可调试 的状态流。

1. 安装依赖

npm install @reduxjs/toolkit react-redux

2. 创建 store

// src/store/index.js
import { configureStore } from "@reduxjs/toolkit";
import userReducer from "./userSlice";

// 创建全局 Store，相当于 Vue 里的 createPinia()
const store = configureStore({
  reducer: {
    user: userReducer, // 注册 user 模块
    // 还可以有其他模块，比如 cart: cartReducer
  },
});

export default store;

3. 定义 Slice（模块）

// src/store/userSlice.js
import { createSlice } from "@reduxjs/toolkit";

// 创建一个 Slice，类似于 Pinia 的 defineStore
const userSlice = createSlice({
  name: "user", // 模块名称
  initialState: {
    name: "游客",
    loggedIn: false,
  },
  reducers: {
    // 登录：设置用户名和登录状态
    login: (state, action) => {
      state.name = action.payload; // action.payload 就是传入的用户名
      state.loggedIn = true;
    },
    // 登出：清空用户信息
    logout: (state) => {
      state.name = "游客";
      state.loggedIn = false;
    },
  },
});

// 导出 action（组件调用时使用）
export const { login, logout } = userSlice.actions;

// 导出 reducer，给 store 使用
export default userSlice.reducer;

4. 在应用入口挂载 Store

// src/main.js
import React from "react";
import ReactDOM from "react-dom";
import { Provider } from "react-redux"; // 提供全局 store 的上下文
import store from "./store";
import App from "./App";

// Provider 让所有子组件都能访问 Redux store
ReactDOM.render(
  <Provider store={store}>
    <App />
  </Provider>,
  document.getElementById("root")
);

5. 在组件中使用 Redux 状态

// src/components/UserInfo.js
import React from "react";
import { useSelector, useDispatch } from "react-redux"; 
import { login, logout } from "../store/userSlice";

function UserInfo() {
  // useSelector 获取全局 state 中的 user 模块
  const user = useSelector((state) => state.user);

  // useDispatch 派发 action，修改全局状态
  const dispatch = useDispatch();

  return (
    <div>
      {user.loggedIn ? (
        <>
          <p>欢迎回来，{user.name}</p>
          <button onClick={() => dispatch(logout())}>退出登录</button>
        </>
      ) : (
        <button onClick={() => dispatch(login("mmx040"))}>
          登录
        </button>
      )}
    </div>
  );
}

export default UserInfo;

五、进阶：异步请求（createAsyncThunk）

在实际项目中，很多全局状态并不是写死的，而是来源于 接口请求。比如：

  • 用户登录后获取用户信息；
  • 获取文章列表、购物车、订单数据；
  • 调用第三方 API 获取天气数据等等。

如果把异步请求逻辑写在组件里，会造成：

  • 状态管理分散：不同组件各自请求数据，难以统一维护。
  • 可读性差：组件既要负责 UI，又要负责逻辑，职责混乱。
  • 难以复用：多个地方用到同样的请求逻辑，只能复制粘贴。

👉 Redux Toolkit 提供的 createAsyncThunk 就是用来解决这个问题的：

  • 它能统一处理 请求的三种状态：pending（请求中）、fulfilled（成功）、rejected（失败）。

1. 定义异步 Action（createAsyncThunk）

// src/store/userSlice.js
import { createSlice, createAsyncThunk } from "@reduxjs/toolkit";

// 定义一个异步 action，用来获取用户数据
// 第一个参数是 action 类型，第二个是异步函数
export const fetchUser = createAsyncThunk(
  "user/fetchUser", // action 类型（命名空间/方法名）
  async (id, thunkAPI) => {
    try {
      const res = await fetch(`https://jsonplaceholder.typicode.com/users/${id}`);
      if (!res.ok) throw new Error("网络错误");
      return await res.json(); // 成功时返回数据，会放到 action.payload
    } catch (error) {
      // 失败时通过 rejectWithValue 返回错误
      return thunkAPI.rejectWithValue(error.message);
    }
  }
);

👉 注意点：

  • id 是传入的参数。
  • thunkAPI 提供了工具（dispatch、getState、rejectWithValue 等）。
  • rejectWithValue 可以在失败时返回自定义错误。

2. 在 Slice 中处理异步状态

const userSlice = createSlice({
  name: "user",
  initialState: { info: {}, loading: false, error: null },
  reducers: {}, // 这里写同步 action
  extraReducers: (builder) => {
    builder
      // 请求中
      .addCase(fetchUser.pending, (state) => {
        state.loading = true;
        state.error = null;
      })
      // 请求成功
      .addCase(fetchUser.fulfilled, (state, action) => {
        state.info = action.payload; // action.payload 就是返回的数据
        state.loading = false;
      })
      // 请求失败
      .addCase(fetchUser.rejected, (state, action) => {
        state.error = action.payload || "请求失败";
        state.loading = false;
      });
  },
});

export default userSlice.reducer;

每个异步 action 自动生成了三个状态：

  • fetchUser.pending → 请求开始。
  • fetchUser.fulfilled → 请求成功。
  • fetchUser.rejected → 请求失败。

这样就能优雅地处理请求的生命周期。

3. 在组件中使用异步 Action

// src/components/Profile.js
import React, { useEffect } from "react";
import { useDispatch, useSelector } from "react-redux";
import { fetchUser } from "../store/userSlice";

function Profile() {
  // 从 store 获取 user 状态
  const { info, loading, error } = useSelector((state) => state.user);
  const dispatch = useDispatch();

  useEffect(() => {
    // 组件挂载时请求用户数据
    dispatch(fetchUser(1)); // 获取 ID=1 的用户
  }, [dispatch]);

  if (loading) return <p>⏳ 加载中...</p>;
  if (error) return <p style={{ color: "red" }}>❌ 出错了: {error}</p>;
  if (!info.name) return <p>暂无用户数据</p>;

  return (
    <div>
      <h2>用户资料</h2>
      <p>用户名：{info.name}</p>
      <p>邮箱：{info.email}</p>
      <p>电话：{info.phone}</p>
    </div>
  );
}

export default Profile;

好处：

  • 组件里不用写 fetch，只要 dispatch(fetchUser(id))。
  • 状态（loading、error、data）都统一在 Redux 管理，逻辑清晰

六、Redux 常用 React Hook、

在 React 里用 Redux，我们最常打交道的就是 三个 Hook：

  • 👉 useSelector
  • 👉 useDispatch
  • 👉 useStore（冷门，很少用）

1. useSelector —— 拿东西的钩子

  • 作用：从 Redux 的 全局仓库 里取数据。
  • 类比：你去仓库拿货（比如账单列表），你要告诉仓库管理员你要哪个货架上的东西。
  • state 就是整个仓库（Redux store）state.user.name 就是仓库里存的用户名。每次 Redux 里的数据更新，这个组件会自动刷新
import { useSelector } from "react-redux";
vv
function Profile() {
  // 从 state.user 模块中拿到用户名
  const username = useSelector((state: any) => state.user.name);

  return <h2>当前用户：{username}</h2>;
}

useSelector 会帮你订阅数据，不用自己写监听。

取数据时要定位到 模块 + 字段。

2. useDispatch —— 发指令的钩子

  • 作用：给 Redux 仓库发消息（action），让仓库里的数据更新。
  • 类比：你不是直接改仓库货物，而是告诉管理员：“帮我把用户名改成 mmx”。
  • dispatch 就是发快递的动作。你传进去的 setName("mmx") 就是快递单（action）。
  • Redux 收到 action 后，仓库里的数据就会更新。
import { useDispatch } from "react-redux";
import { setName } from "./store/userSlice"; // 你定义的 action

function ProfileUpdater() {
  const dispatch = useDispatch();

  return (
    <button onClick={() => dispatch(setName("mmx"))}>
      修改用户名为 mmx
    </button>
  );
}

React 组件里不能直接改全局数据，只能通过 dispatch。

Redux 的设计理念就是 单向数据流：发 action → reducer 处理 → store 更新 → 组件刷新。

3. useStore —— 直接拿整个仓库

  • 作用：返回 Redux 的 store 实例。
  • 类比：直接拿到仓库的钥匙，你能看到里面所有货物，还能自己调用 store.getState()。
  • 很少在业务里用，一般在调试或封装库时用。
import { useStore } from "react-redux";

function Debugger() {
  const store = useStore();
  console.log("当前仓库里的数据:", store.getState());

  return null; // 不展示 UI，只是调试
}

useStore 比较底层，平时开发几乎不用。

4. 配合 useEffect 一起用

实际项目里，常常需要在页面加载时 dispatch 一个异步请求。

import { useEffect } from "react";
import { useDispatch, useSelector } from "react-redux";
import { fetchUserList } from "./store/userSlice";

function UserList() {
  const dispatch = useDispatch();
  const users = useSelector((state: any) => state.user.list);

  // 页面加载时，自动请求一次数据
  useEffect(() => {
    dispatch(fetchUserList());
  }, [dispatch]);

  return (
    <ul>
      {users.map((u: any) => (
        <li key={u.id}>{u.name}</li>
      ))}
    </ul>
  );
}

  • 组件挂载时执行 dispatch(fetchUserList())。

  • Redux 接到这个 action，会去请求数据，然后更新 state.user.list。

  • 组件里的 useSelector 会自动感知变化，刷新页面。
